# 统一实验与运维协议

本文档整合此前的工作协议。`latent-register/` 下的四份文件仍是历史实验的冻结源码权威；
本文档约束冻结树以外的新工作。

## 权威顺序

1. 用户当前的明确决定。
2. 被复现实验的冻结源码与协议。
3. 已打开且通过校验和验证的制品及其精确源码目录。
4. 本统一协议与论文表格台账。
5. 历史说明文字、聊天、目录名或日志。

冲突按上述顺序解决。较新的文字摘要不能覆盖制品、源码固定版本、预注册划分或不可变部署。

## 全局不变量

- 禁止修改 `latent-register/`。
- 禁止原位修改已提交的部署；必须创建新的不可变版本。
- 保留原生 Slurm 依赖；禁止绕过 `afterok`。
- 禁止读取部分 qrels、部分 Hit@3 或运行中的分数文件。
- 禁止删除 qrels、合并 exact API、选择碰撞中的最后一个成员，或放宽一一对应的物理身份。
- 必须区分负面/空结果与基础设施失败。
- 调度器的 `COMPLETED 0:0` 只证明进程正常退出，不证明科学有效性。
- 不得恢复用户已删除的基线。

## Late-Bound 部署合同

每个已注册 API 必须证明：

```text
每个不同 API 仅进行一次有界文档前向
注册时优化器步数为零
API 专属学习参数为零
backbone/compiler/tokenizer/静态行改动为零
物理 token ID 原子化且互不相同
一个 exact identity -> 一个逻辑槽位 -> 一个物理 ID
最终分母保留普通词表
未激活的预留地址被屏蔽
获胜物理 ID -> 同一身份 -> 自己的载荷
```

禁止把训练期物理 ID 轮换宣称为学习机制。允许使用确定性占位地址。评测可以使用任意从未
暴露的地址；地址置换属于审计。

顺序追加必须保留完全相同的旧身份/槽位/地址前缀。用同一个 seed 重新构建两个 registry
并不足以证明此前映射被保留。

## 数据与评测合同

### STQ 主面板

| 数据群体 | 数量 | 访问规则 |
| --- | ---: | --- |
| 已见 API | 999 | 共享训练 |
| 已见训练查询 | 10,483 | 仅训练 |
| 已见开发查询 | 1,707 | 仅选择 checkpoint |
| 未见 API | 837 | 冻结后注册并进行完整排序 |
| 测试查询/qrels | 1,066 | 先生成预测；仅终态审计可读取 qrels |

每种方法都必须对全部 837 个 exact identity 排序。禁止 shortlist、家族分、感知 qrel 的
剪枝、合并文档或按源码顺序打破平分。平分时先按分数降序，再按 exact identity 字典序。

正式学习方法行使用 seed 17/29/43，并固定数据划分、查询顺序、候选顺序、registry seed
和评测器；只改变模型初始化与训练顺序。报告 Hit@1/3/5、Recall@5、MRR、平均排名、
配对 bootstrap 区间、最大 Top-1 hub、不同 Top-1 数量、碰撞/身份有效性，以及零步与
静态改动审计。

### ToolBench

官方 ToolGen I1/G1、I2/G2 和 I3/G3 轨道必须与受控 exact-API 面板分开。报告与论文
兼容的 NDCG 和修正 NDCG，因为官方评测器构造理想 DCG 时，可能只使用预测 beam 中
出现的相关工具。清单允许时，还要报告 exact API Hit@k/MRR。

发布 token 组不等同于精确物理身份。已审计的 G1 碰撞制品是严格身份主张的硬阻塞项。

### 外部 benchmark

- BFCL 官方分数要求固定 Gorilla 源码、数据、类别、评测器和官方候选集。按类别建立完整
  registry 的压力测试属于单独的机制 benchmark。
- Tau2 使用配对的 `(domain, task_id, trial, simulator seed)` 单元。不完整的 domain array
  永远不得聚合。
- StableToolBench 继续暂停。没有明确恢复指令和凭据授权，不得调用付费 simulator/judge API。
- MCPEvol/ContDa 和 E5/BM25 是诊断，不能填写 STQ 或 ToolBench 方法单元格。

选择、参数生成和任务完成始终是不同的指标族。检索 top-k 绝不能改称官方多调用 exactness。

## 仅源码对照策略

正式对照行必须执行公共上游核心：

| 方法 | 固定源码版本 | 核心边界 |
| --- | --- | --- |
| CoTools | `external/Chain-of-Tools`，commit `bd67fd8743082639a8b81dff724504bdcb3d0527` | 上游模型、损失、训练/推理对象 |
| ToolScalER | `external/Toolscaler-a72d46d`，commit `a72d46d3352358f39a9274aeb8bf8217b164bb01` | `GenCodebook`、`E2eTraining`、评测器核心 |
| Native | 冻结的 `latent-register/` | 从外部调用冻结的训练/评测模块 |

允许的适配：绝对路径、环境、输入清单与已声明过滤、Slurm 资源/依赖、输出路径、保持 schema
不变的收集、校验和、泄漏审计和独立指标重算。

禁止的适配：重写或 monkey-patch 模型、损失、tokenizer、retriever、compressor、scorer、
decoder 或评测器行为。

执行顺序：

1. 导入/编译官方源码，并运行最小真实上游 smoke。
2. 在资产和 checkpoint 存在时，运行原生源码划分/复现。
3. 之后才可进行匹配迁移，并明确标注为迁移。
4. 保留原生指标，并以单独名称增加修正/精确指标。

缺少 checkpoint、数据集或上游评测器属于阻塞，不能因此替换成 clean-room 代码。

## 证据准入

论文数值单元格必须同时满足：

1. 冻结的数据群体、精确身份单元、分母和排除项；
2. 源码 commit/目录、模型/tokenizer 版本、输入、划分和命令；
3. 完整原始 Slurm 血缘与终态；
4. 制品目录和有效的 `COMPLETE` 绑定；
5. 发生训练时的 checkpoint/完整模型重载；
6. 访问指标前，已经生成不接触 qrel 的完整预测矩阵；
7. 评测器/指标哈希和独立重聚合；
8. 逐样本预测与规范参考答案；
9. 正式学习方法行所需的 seeds 和配对不确定性；
10. Native 的零步、改动、地址、碰撞和自有载荷审计。

`PENDING` 表示声明的制品缺失或未审计。`BLOCKED` 表示当前输入违反合同。`N/A` 由方法
定义，绝不表示零。完整审计得到 `passed=false` 仍是有效的负面实验。

## 算力边界

当前规划范围：

| 资源 | 容量 | 用途 |
| --- | ---: | --- |
| A100 | 最多一张 GPU | 短 smoke、推理、审计或经过测量的单卡训练 |
| L20 | 最多四张 GPU | 分片、计时和通过资源预检的训练 |
| 历史 A100 x6 | 新任务不可用 | 仅保留来源信息 |

每个制品必须记录 `resource_profile`、world size、精度、分片/offload 模式、有效 batch、
峰值显存和 wall time。smoke 不能填写完整训练行。四张 L20 替代任务属于新分支，不能
冒充历史六张 A100 结果。

## Slurm 修复循环

长实验按以下流程执行：

1. 提交一条带原生 `afterok` 依赖的不可变 DAG。
2. 提交后立即用 `scontrol` 验证每条依赖。
3. 启动一个分离式 watcher，每 900 秒轮询一次终态审计。
4. 每个 15 分钟窗口后只检查调度器状态和 stage/step 数；禁止读取运行中指标。
5. 只有终态失败后才打开失败任务的终态日志。
6. 取消不可达后继任务，并停止过期 watcher 进程组。
7. 将诊断限制在最小因果边界；创建新的不可变版本。
8. 重新计算 `SOURCE.sha256`，对每个阶段运行测试/编译/shell 检查、远端校验和、parser
   检查和 `sbatch --test-only`。
9. 将远端部署冻结为只读，重新提交并重复上述流程。
10. 只有终态审计、哈希、`COMPLETE`、重载和指标重聚合全部通过后才停止。

禁止高频轮询集群。SSH keepalive 和机械 watcher 是运维工具，不是周期性聊天自动化。

## 代码组织

| 路径 | 含义 | 编辑规则 |
| --- | --- | --- |
| `latent-register/` | 冻结原始树 | 禁止编辑 |
| `worktrees/active/<name>-vN/` | 开发血缘 | 行为改变必须创建新版本 |
| `worktrees/deferred/` | 暂停工作 | 仅在明确决定后恢复 |
| `deployments/<name>-vN/` | 已提交快照 | 不可变 |
| `ops/` | 跨实验机械工具 | 保留被引用的版本 |
| `paper-evidence/` | 已收集制品 | 追加新证据包；禁止改写 |
| `external/`、`baselines/` | 固定源码/资产 | 记录版本和许可证 |

新代码应分离 exact identity、registry 事务、清单改动、文档编译、评测和制品/校验和处理。
生成的 `.DS_Store`、`__pycache__`、`.pytest_cache`、`.ruff_cache`、空 marker 和过期 PID/
日志文件可以删除，除非已经被证据目录收录。

## 保留策略

本地保留正式审计、聚合、独立重算所需的逐样本预测、清单、哈希和完成标记。只有当分支
确定没有论文资格且存在经过验证的恢复来源时，才可删除诊断性的原始训练 tensor/checkpoint。
不得把本地裁剪后的证据包宣称为完整重放包。

凭据绝不能写入文档、部署、日志或制品。
